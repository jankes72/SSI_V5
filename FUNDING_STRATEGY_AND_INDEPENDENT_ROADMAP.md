# SSI V5 — Funding Strategy and Independent Development Roadmap

**Status:** `PUBLIC STRATEGY / PRE-T0`  
**Updated:** `2026-09-04`  
**Author:** Paweł Jankiewicz  
**Purpose:** explain what external funding can accelerate, what it cannot replace, what has already been built without such funding, and how SSI V5 continues if no grant is obtained.

---

## 1. Core position

SSI V5 is **not dependent on receiving a grant in order to continue**.

The current architecture, implementation work, migration/hardening process and public evidence were developed independently using the author's existing hardware together with local, free or otherwise available model/tool infrastructure.

The funding thesis is therefore:

```text
NO GRANT
!=
NO SSI

GRANT
=
FASTER INFRASTRUCTURE
+ LARGER EXPERIMENTS
+ MORE PARALLEL VALIDATION
+ EXTERNAL VALIDATION
+ FASTER ACCESS TO PHYSICAL / EMBODIED DOMAINS
```

External funding is treated as an **acceleration mechanism**, not as the condition that makes the project possible.

The immediate objective is to continue building the system independently toward a stronger `T0 / Frozen Baseline`.

The intended progression is:

```text
CURRENT PRE-T0
-> CONTINUUM professional closure / hardening
-> canonical Interface <-> ROBERT <-> CONTINUUM visibility
-> canonical skill baseline / registry / selection evidence
-> TEST 6 full SSI BODY integration experiment
-> T0 FROZEN BASELINE
```

The purpose of this work is to reduce the amount of the proposal that depends on promises and increase the amount that can be shown as already implemented and tested.

## 4. What happens without a grant

If no external funding is received, development continues in stages on the available infrastructure.

The intended independent path includes:

```text
SSI BODY T0
-> ROBERT programming / engineering capabilities
-> DIRECTOR practical work domains
-> first economic / software execution loops
-> reinvest part of positive outcomes into infrastructure
-> progressively stronger local hardware
-> larger experiments when resources permit
```

A practical long-term objective is for useful work performed through ROBERT / Director domains — for example software engineering and later selected economic workflows — to help finance additional infrastructure if those experiments produce positive real-world outcomes.

This is a development objective, not a guarantee of profitability.

## 5. What a grant changes

A grant would primarily change **time, scale and experimental reach**.

### 5.1 Compute and infrastructure

Funding could provide:

- stronger GPU hardware;
- larger RAM / storage / fast local state infrastructure;
- multiple independent execution nodes;
- more parallel stress tests and agent experiments;
- stronger local models where useful;
- controlled access to paid model/API providers for comparison and validation.

### 5.2 Faster experimental programme

Instead of waiting for infrastructure to grow gradually from available resources, funding could allow several research tracks to run earlier and in parallel.

Examples:

```text
WITHOUT FUNDING
sequential growth
-> infrastructure upgrade
-> next experiment
-> next upgrade

WITH FUNDING
T0
-> parallel validation
-> larger agent series
-> external benchmarks
-> physical / embodied demonstrators
-> independent reproduction
```

### 5.3 Independent validation

One of the most valuable uses of funding would be work that the author should not evaluate alone:

- independent technical review;
- external benchmark design;
- adversarial testing;
- reproducibility work;
- security and authority-boundary review;
- scientific/statistical methodology support;
- external hardware/laboratory validation where applicable.

The value of the grant is therefore not only more compute. It can increase the **independence and credibility of evidence**.

---

## 6. What a grant does NOT change

A grant does not:

- create the original SSI architecture retroactively;
- replace the existing authorship/provenance history;
- change the highest-level research question merely to fit a programme;
- justify claiming untested functionality;
- turn hypotheses into validated results;
- make a failed experiment disappear;
- make SSI dependent on continuing subsidies;
- require future experimental branches to become part of the SSI core architecture.

The project should continue to preserve the same rule:

```text
CLAIM
-> TEST
-> EVIDENCE
-> AUDIT
-> REPAIR IF NEEDED
-> RETEST
-> CLAIM BOUNDARY
```

Funding changes execution capacity, not the standard of proof.

## 7. Why additional domains matter — and what they are NOT

Future domains such as **robotics, drones / autonomous platforms or other technology fields** are not automatically parts of SSI BODY.

Their stronger research role is as **external derived-project / transfer tests**.

After a frozen micronetwork baseline exists, a future experiment can ask:

```text
FROZEN SSI / MICRONETWORK BASELINE
-> NEW EXTERNAL PROJECT BRIEF
-> SELECT EXISTING VERIFIED COMPETENCES
-> IDENTIFY MISSING COMPETENCES
-> BUILD A NEW PROJECT
-> TEST THE PROJECT
-> RECORD WHICH COMPETENCES TRANSFERRED
-> RECORD WHAT HAD TO BE CREATED
-> PRESERVE SSI BASELINE
```

This can test whether the micronetwork/competence technology is reusable outside the environment in which it was developed.

The correct claim would not be:

> "SSI already knows robotics or drones."

The stronger and more falsifiable question is:

> **Can a frozen, previously validated SSI competence substrate be used to create new independent projects in domains that were not part of the baseline project?**

At first, software/simulation demonstrators may be sufficient to test transfer mechanics. Physical robotics or drone experiments would require additional hardware, safety engineering, facilities and domain-specific validation; those are examples of areas where funding could materially accelerate the programme.

---

## 8. Why physical domains are lower priority without funding

Without dedicated resources, the author does not need to divert the project away from the main SSI experiment merely to purchase hardware for every possible application domain.

The priority remains:

```text
BUILD AND VALIDATE SSI CORE MECHANISMS
FIRST

THEN
USE FROZEN BASELINES TO TEST TRANSFER
```

Therefore robotics, drones and other physical domains are optional expansion tracks. They become especially useful when external funding makes the required hardware and independent validation practical without slowing the main SSI roadmap.

---

## 9. Funding should accelerate the experiment, not redefine it

The intended relationship is:

```text
SSI ROADMAP
exists independently

GRANT
joins the roadmap
and accelerates selected milestones

NOT

GRANT CALL
-> redesign SSI only to match the call
```

A proposal can select the part of SSI that is relevant to a funding programme, but the public project history should continue to distinguish:

- existing architecture;
- already validated mechanisms;
- planned experiments;
- grant-enabled acceleration;
- grant-specific work packages.

## 10. Current funding scale examples — not promises of eligibility

The following are **examples of currently available/relevant funding scales as of 2026-09-04**. They are not claims that SSI currently satisfies every eligibility or readiness requirement.

### Polish / startup acceleration level

**StartupsExchange by StartSmart CEE (PARP)**

- support up to `100,000 PLN`;
- first round opens `2026-09-07`;
- aimed at Polish startups with international potential.

Official source: https://en.parp.gov.pl/component/grants/grants/startupsexchange-by-startsmart-cee

**Startup Booster Poland — Scale Up Green (PARP)**

- startup support up to `400,000 PLN`;
- current programme page lists applications through `2027-09-30`.

Official source: https://feng.parp.gov.pl/component/grants/grants/startup-booster-poland---oferta-dla-startupow

These programmes are examples of smaller acceleration-level support. Their relevance depends on company/startup status and the specific accelerator track.

### European deep-tech research level

**EIC Pathfinder 2026**

- grants up to approximately `EUR 4 million`;
- designed for early-stage visionary / breakthrough deep-tech research;
- 2026 Pathfinder Challenges include `DeepRAP — Deep Reasoning, Abstraction & Planning towards trustworthy Cognitive AI Systems`;
- 2026 Challenges deadline: `2026-10-28`.

Official sources:

- https://eic.ec.europa.eu/eic-funding-opportunities/eic-pathfinder/eic-pathfinder-challenges-2026_en
- https://eic.ec.europa.eu/eic-funding-opportunities/eic-2026-work-programme_en

Pathfinder is a much more demanding research target than a small startup accelerator. A thematic fit does not imply a high probability of award.

### Later commercial scale-up level

**EIC Accelerator**

- grant component below `EUR 2.5 million`;
- potential EIC Fund equity investment up to `EUR 10 million`;
- aimed at startups/SMEs developing and scaling market-creating or market-disrupting innovation, typically around TRL 6-8.

Official source: https://eic.ec.europa.eu/eic-funding-opportunities/eic-accelerator_en

This is presented as a later-stage route, not as the current baseline status of SSI.

## 11. What an ideal grant would buy for SSI

The strongest use of funding would be a package combining:

```text
COMPUTE
+ INDEPENDENT VALIDATION
+ EXPERIMENTAL HARDWARE
+ DOMAIN EXPERTISE
+ REPRODUCIBILITY
+ TIME TO RUN LARGER LONGITUDINAL EXPERIMENTS
```

A good grant therefore does not merely pay for development that would otherwise never happen. It should allow the same research trajectory to reach stronger evidence sooner and test questions that are currently expensive in time or physical infrastructure.

---

## 12. Current author / project position

The current position can be summarized as:

> **SSI V5 is being developed whether or not external funding is obtained. The existing system and evidence establish a real development trajectory before funding. External support would primarily shorten the path to stronger infrastructure, larger longitudinal experiments, independent validation and physical-domain transfer tests. If no funding is obtained, the project continues sequentially using available/free infrastructure and, where future practical work produces positive outcomes, gradual reinvestment into SSI infrastructure.**

This position is intentionally different from:

> "The project can begin only if a grant is awarded."

This document is a **funding strategy and roadmap statement**, not a technical result and not a financial forecast.
