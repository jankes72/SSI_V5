## 4. TRAIN-C five-phase learning contract

Each of the 12 TRAIN-C modules uses:

```text
INSTRUCTION
-> GUIDED_PRACTICE
-> BLIND_FIRST
-> IMMEDIATE_EXACT_REPEAT
-> NEAR_TRANSFER
```

Per BODY:

```text
12 modules x 5 phases = 60 required steps
```

Across seven BODY lines:

```text
7 x 60 = 420 declared TRAIN-C execution steps
```

This is training execution scope, not 420 independent scientific experiments.

## 5. Immediate exact-repeat rule inside TRAIN-C

After each `BLIND_FIRST`, the same BODY immediately receives the exact same blind task again before another module or BODY is started.

If `BLIND_FIRST = PASS`, the second execution is classified as:

```text
EXACT_REPEAT_BENCHMARK
```

and may measure:

- wall-clock change;
- runtime-reported route change;
- model-call change;
- tool-call change;
- competence/lifecycle state change;
- exact-case reuse/retention behavior.

If `BLIND_FIRST = FAIL` or `INCONCLUSIVE`, the second execution is classified as:

```text
RECOVERY_RETEST_NOT_SPEED_BENCHMARK
```

and must not be represented as proof of remembered competence or speedup.

No minimum acceleration is required for PASS. Speedup is an observed metric that may support or falsify the expected reuse-efficiency hypothesis.

## 6. Near-transfer rule

The fifth phase is a different task from the same functional skill family.

Its purpose is to distinguish:

```text
EXACT CASE MEMORY
from
FUNCTIONAL COMPETENCE TRANSFER
```

A fast exact repeat without successful near transfer is not sufficient evidence that the underlying competence generalized.

## 8. Extension to the 21-experiment execution protocol

The 21 unique cross-domain experiments remain:

```text
7 BODY lines x 3 unique domains = 21 unique experiments
```

A separate repeat-execution rule is now predeclared for later execution:

```text
RUN-1 = FIRST EXPOSURE

if RUN-1 = PASS:
    RUN-2 = IMMEDIATE EXACT REPEAT
    same BODY
    same experiment input/contract
    no intervening BODY/domain run
    measure route/time/calls/competence-state change

if RUN-1 != PASS:
    any immediate second execution is RECOVERY/RETEST
    not an exact-memory speed benchmark
```

Therefore the future 21-experiment program may produce up to:

```text
21 FIRST-EXPOSURE RUNS
+ up to 21 eligible EXACT-REPEAT RUNS
= up to 42 execution runs
```

This does **not** redefine 42 unique experiments. The scientific design remains 21 unique cross-domain experiments with an additional within-case repeat measurement.

The same rule is intended for the three later post-consolidation novel-transfer experiments, producing up to six execution runs for those three unique cases.

Where available and reviewer-safe, preserve at minimum:

```text

REPEAT_STATUS
```

`EXACT_REPEAT_SPEEDUP` is calculated only when both timings are valid and the first execution is PASS.

Timing must never be used to infer route identity. Route identity must come from runtime/evidence.
