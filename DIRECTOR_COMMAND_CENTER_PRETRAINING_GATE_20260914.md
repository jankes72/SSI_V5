## Relationship to DIRECTOR

The Command Center is **not a second Director runtime**.

It is an operational presentation and aggregation layer around the existing canonical Director line.

Current intended separation:

```text
DIRECTOR
= canonical organizational / coordination / planning line
= own runtime, state, CONTINUUM, memory and evidence lineage

DIRECTOR COMMAND CENTER
= professional owner/operator surface
= organization-wide aggregation and navigation

```

The existing local developer view remains available as a technical surface. The Command Center adds a higher-level operational view rather than replacing the lower-level engineering diagnostics.

## Command Center information model

The implemented interface is organized around SSI as an evolving operational/research organization rather than only around process health.

Prepared top-level areas include:

```text
COMMAND / CURRENT OBJECTIVE
```

The long-term intent is that the operator can see not only whether a process is online, but also:

- what changed;
- which agent or line produced a new competence;
- which evidence supports it;
- whether S10 classified it as Candidate / Challenger / Champion / Specialist / Hold;
- whether a later controlled integration made it available to ROBERT, BODY_FROZEN 2.0 or DIRECTOR;
- whether a project/order is active;
- whether a verified result changed organizational state;
- whether the Technology Radar found a candidate technology;
- whether financial sources are connected or still unavailable.

## Skill / competence flow boundary

The Command Center explicitly reserves a visible competence-transfer path.

The intended controlled sequence is:

```text
ISKRA / BODY / LAB DISCOVERY
-> EVIDENCE
-> FUNCTIONAL IDENTITY / COMPARISON
-> S10 LIFECYCLE DECISION
-> REGRESSION / ACCEPTANCE WHERE REQUIRED
-> VERSIONED INTEGRATION
-> ROBERT / BODY_FROZEN 2.0 / DIRECTOR AVAILABILITY
```

This is **not** an automatic rule that every skill created by an agent is copied into every canonical system.

A new competence must retain provenance and pass the applicable promotion/integration gates. This is consistent with the existing ROBERT continuity and post-experiment consolidation rules.

## Hermes role in the Command Center

Hermes is assigned an operator-guidance and change-summary role rather than independent ROOT authority.

The interface prepares a delta-oriented feed intended to answer questions such as:

```text
WHAT CHANGED SINCE THE LAST SNAPSHOT?
DID AN AGENT CREATE OR PROMOTE A COMPETENCE?
DID A PROJECT OR ORDER CHANGE STATE?
DID A TEST / EXPERIMENT PRODUCE NEW EVIDENCE?
DID DIRECTOR CREATE A NEW ASSIGNMENT?
DID TECHNOLOGY RADAR FIND A NEW CANDIDATE?
DID AN INTEGRATION BECOME AVAILABLE / FAIL / RECOVER?
DID CAPITAL / PROFIT STATE CHANGE AFTER A REAL SOURCE IS CONNECTED?
```

Hermes reports changes; it does not silently become a second Director or a second scientific auditor.
