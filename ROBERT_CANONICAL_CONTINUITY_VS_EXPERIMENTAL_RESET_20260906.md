# SSI V5 — ROBERT Canonical Continuity vs Experimental Reset

**Recorded:** `2026-09-06`  
**Status:** `PROJECT-STATE DECLARATION / CANONICAL ROBERT CONTINUITY`  
**Purpose:** prevent a critical misunderstanding between the evolving canonical ROBERT line and cleaned/frozen experimental BODY artifacts.

## 1. The key distinction

Preparing `BODY_FROZEN` and the BODY ISKRA experimental descendants did **not** mean deleting the historical competence, memory or validated development state of canonical ROBERT.

The experimental reset/cleaning applies to the experiment artifacts used to establish controlled starting conditions.

```text
CANONICAL ROBERT
= continuous engineering / execution line
+ historical development state
+ retained memories / learned competence / validated skills from prior work
+ TEST 1 -> TEST 5 lineage remains part of ROBERT's development history

BODY_FROZEN / BODY ISKRA EXPERIMENT ARTIFACTS
= controlled experimental branches
+ cleaned/frozen where required by protocol
+ isolated start states
+ designed to prevent prior experimental contamination
```

Therefore:

```text
CLEAN EXPERIMENT COPY
!=
ROBERT FORGETS ITS HISTORY
```

## 2. Why this matters

SSI V5 currently has two different but connected trajectories.

### Experimental trajectory

```text
BODY_FROZEN
-> controlled cross-domain experiments
-> BODY ISKRA 1-6
-> independent experience
-> Candidate / Challenger / Champion
-> validated competence comparison
-> later consolidation / upgraded descendant
```

This trajectory needs frozen or cleaned states so later results can be compared fairly.

### ROBERT engineering trajectory

```text
HISTORICAL ROBERT
-> TEST 1
-> TEST 2
-> TEST 3
-> TEST 4
-> TEST 5
-> retained memory / validated competence / tooling lineage
-> Eyes / Hands / execution expansion
-> later intake of newly validated skills
```

ROBERT is not reset to zero simply because experimental copies are reset for research control.

## 3. TEST 1-5 history is not disposable

The earlier test series is part of the engineering lineage that produced the current ROBERT/SSI runtime path. Failures, repairs, persistence behavior, routing evidence, authority boundaries, recovery behavior and other validated mechanisms remain part of that development history.

The public TEST 5 evidence already records, among other things:

```text
ROBERT_STABLE = 46/46 PASS
TEST5_ACCEPTANCE = 29/29 PASS
TOTAL = 524/524 PASS
```

This public evidence supports continuity of the tested ROBERT/runtime engineering line through TEST 5. It does **not** publicly enumerate every private retained memory item or every private skill record. Those private runtime details remain outside the evidence-only mirror.

## 4. Experimental cleaning is branch-local

The purpose of cleaning/freeze operations is methodological:

- create a fair baseline;
- isolate new experience;
- make later skill formation attributable to the experiment;
- avoid silently importing prior private experience into a supposedly clean comparison line;
- preserve a known T0 state.

It is **not** a destructive instruction to erase the canonical ROBERT development line.

```text
ROBERT CANONICAL STATE
        |
        +---- remains continuous
        |
        +---- experiment preparation creates isolated branches
                         |
                         +-> BODY_FROZEN
                         +-> ISKRA 1
                         +-> ISKRA 2
                         +-> ISKRA 3
                         +-> ISKRA 4
                         +-> ISKRA 5
                         +-> ISKRA 6
```

## 5. Future skill flow

Future experimentally validated skills may later be made available to ROBERT under explicit promotion/integration gates.

That does not mean ROBERT starts empty before those future skills arrive. It means ROBERT has an existing historical competence/tooling baseline and can later receive additional validated competence from the experimental program.

```text
ROBERT EXISTING COMPETENCE
+
NEW EXPERIMENTALLY VALIDATED SKILLS
-> controlled integration
-> regression / acceptance
-> expanded ROBERT capability
```

ROBERT and the Director can therefore continue their own engineering evolution in parallel with the research experiment lines.

## 6. Public/private boundary

PUBLIC:

- the distinction between canonical ROBERT and cleaned experimental branches;
- the fact that TEST 1-5 remain part of ROBERT's engineering lineage;
- sanitized validation results such as TEST 5;
- future skill provenance and promotion status where publishable.

PRIVATE:

- raw memory stores;
- exact private skill inventory where not intentionally sanitized;
- implementation-level ROBERT state;
- source code and internal file tree;
- proprietary integration details.

## 7. Claim boundary

This document should not be read as a public machine-verifiable enumeration of every retained ROBERT memory or skill. It records the project-state and architecture distinction needed to interpret the experiment correctly.

The core public statement is:

> **Canonical ROBERT remains the continuous engineering/execution line carrying its prior validated development history. BODY_FROZEN and BODY ISKRA are isolated experimental branches prepared for controlled research. Cleaning an experimental branch does not erase ROBERT's historical skills or memory.**
