# SSI V5 — Research Programme Lineage and Post-S40 Comparative Plan

**Date:** 2026-10-04  
**Role:** current lineage / continuity document for technical, grant and research review.  
**Project model:** independently developed long-horizon SSI R&D programme.  
**Current boundary:** historical milestones are evidence-backed only within their published scopes; future S40 / WEB comparisons are preregistered plans, not completed results.

## 1. SSI is a continuing research programme, not a grant-specific project

SSI V5 did not originate as a funding application or as a one-off Evidence project. The public repository preserves a development sequence that predates the current grant application and documents the system from its earlier competence, routing, consolidation and training layers through the present reliability/evidence work.

The current Evidence / repair programme is therefore a **focused research track inside an existing SSI research programme**. Funding would extend the scale and independence of measurement; it would not create SSI from zero.

The public history should be read as:

~~~text
PERSISTENT COMPETENCE / MICRONETWORKS
-> ROUTER V10
-> ROUTER S10
-> CONTROLLED S1-S10 TRAINING / CONSOLIDATION
-> POST-S10 DOMAIN TRANSFER
-> S11-S40 LONG-HORIZON R&D TRAINING
-> EVIDENCE / ZEROLAB / REPAIR HARDENING
-> FROZEN S40 ACTOR STATE
-> COMPARATIVE WEB LEARNING
-> VISUAL ARTIFACT / BEHAVIORAL / AFFECT-LIKE LONGITUDINAL STUDY
-> LATER EXTERNAL / PARTNER-DEFINED VALIDATION
~~~

This chronology matters because later experiments inherit state, skills, routing history and evidence from earlier layers rather than being isolated demonstrations.

## 2. Micronetworks — persistent competence before long-horizon comparison

The competence layer was designed so that useful results are not merely temporary model responses.

Public architecture records define the broad lifecycle as:

~~~text
EXPERIENCE
-> CANDIDATE
-> VALIDATION
-> CHALLENGER / CHAMPION / SPECIALIST / HOLD
-> PERSISTENT MICRONETWORK COMPETENCE
-> LATER REUSE / COMPOSITION / RETEST
~~~

The key research idea is persistence with provenance: competence has identity, history, qualification state and a controlled route to later reuse.

Micronetworks are therefore an earlier foundation for the later longitudinal study. A post-S40 comparison can ask not only whether two actors answer differently, but whether they built, retained and reused different competence structures.

- [Complete Ecosystem Architecture](SYSTEM/SSI_COMPLETE_ECOSYSTEM_ARCHITECTURE_20260917.md)

## 3. Router V10 — state- and history-aware competence access

Router V10 is documented as more than semantic lookup or a cache.

Its role includes:

- task/state-aware routing;
- competence selection;
- attempt-history awareness;
- confidence gating;
- failure-signature awareness;
- false-reuse protection;
- anti-loop behavior;
- controlled escalation to deeper/full flow.

The intended behavior is:

~~~text
HIGH CONFIDENCE + VALID HISTORY
-> REUSE

AMBIGUOUS
-> VERIFY

REPEATED FAILURE / NEGATIVE HISTORY
-> CHANGE ROUTE / RECOVER / ESCALATE

LOW / UNKNOWN / CONFLICT
-> FULL FLOW
~~~

This layer makes later actor comparison more meaningful because the research can measure not only final success, but **which route an actor selected and how its route selection changed with experience**.

Primary reference:

- [V10 — Stateful Predictive Competence & Recovery Router](V10_PREDICTIVE_ROUTING.md)

## 4. Router S10 — cross-line comparison and controlled consolidation

Router S10 operates at a different level from V10.

V10 is primarily within-body competence/routing logic. S10 is documented as the cross-line comparison/consolidation layer that can:

- collect competence from separate actor histories;
- group related competence;
- compare evidence;
- rank candidates;
- propose Champion / Challenger / Specialist / Hold outcomes;
- prepare controlled consolidation;
- preserve provenance;
- produce versioned descendants;
- require target-specific retesting.

This establishes an important SSI principle:

~~~text
LOCAL LEARNING
!=
CROSS-ACTOR CONSOLIDATION
~~~

An ISKRA can change locally without its state being silently copied into every other actor.

That separation is essential for the post-S40 study because BODY_FROZEN and ISKRA1..ISKRA6 must retain distinguishable histories if their later behavior is to be compared scientifically.

Primary reference:

- [Complete Ecosystem Architecture — Router S10 section](SYSTEM/SSI_COMPLETE_ECOSYSTEM_ARCHITECTURE_20260917.md)

## 7. S11-S40 — long-horizon R&D training, not yet the visual WEB experiment

S11-S40 is the current long-horizon R&D training path.

Its purpose is broader than producing web pages or graphics. It exercises and develops the SSI research machinery around:

- problem solving;
- competence creation;
- skill qualification;
- routing;
- reuse/adaptation/full flow;
- independent actor histories;
- failure handling;
- recovery;
- review;
- evidence;
- consolidation boundaries.

This phase is where the actors accumulate longer histories from which later differences can be measured.

The current repair work exists precisely because a long-horizon comparison is not useful if the measurement path itself is unreliable. ZeroLab, Evidence V3 and the continuing repair harden the mechanisms that distinguish:

~~~text
REAL ACTOR DIFFERENCE
from
MEASUREMENT / REVIEW / INFRASTRUCTURE ERROR
~~~

## 8. Why S40 is the critical longitudinal boundary

The key future measurement is not the S10 snapshot alone.

After evidence-valid completion through S40, the programme intends to freeze a separately identified state for:

~~~text
BODY_FROZEN
ISKRA1
ISKRA2
ISKRA3
ISKRA4
ISKRA5
ISKRA6
~~~

The S40 freeze is intended to bind, where available:

- actor/runtime identity;
- model/provider identity;
- base-model/weight identity;
- persistent skill inventory;
- Micronetwork / BLOCKS state;
- memory/lifecycle checkpoint;
- routing statistics;
- reuse/adapt/full-flow history;
- failure/recovery/rollback history;
- evidence head;
- affect-like state snapshot;
- cost/model-call counters.

This creates a scientific baseline for asking how each actor changed over the long S11-S40 period.

The comparison is therefore:

~~~text
EARLY / INITIAL ACTOR STATE
-> S1-S10 FOUNDATION
-> S11-S40 LONG-HORIZON R&D HISTORY
-> FROZEN S40 ACTOR STATE
-> MEASURED DELTA
~~~

The programme must preserve actor-specific trajectories instead of averaging ISKRA1..ISKRA6 into one score.

## 9. WEB begins a new observational phase

WEB01-WEB24 is not just "more training".

It is intended to be the first planned phase where internal differences can be observed simultaneously in:

1. **competence acquisition**;
2. **learning path**;
3. **persistent state change**;
4. **visible generated artifacts**.

Each actor starts from its own frozen S40 state and receives the same declared WEB curriculum family.

Primary comparison:

~~~text
BODY_FROZEN@S40 ----\
ISKRA1@S40 ----------\
ISKRA2@S40 -----------\
ISKRA3@S40 ------------> SAME WEB CURRICULUM
ISKRA4@S40 -----------/        |
ISKRA5@S40 ----------/         v
ISKRA6@S40 ---------/    FROZEN POST-WEB STATES
~~~

The primary study should isolate actors from cross-agent knowledge promotion so that their own learning paths remain measurable.

A later secondary phase may intentionally enable consultation/consolidation to measure what knowledge transfer changes.

## 10. WEB produces physically observable comparison artifacts

WEB output adds something that the earlier R&D curriculum does not provide as directly: rendered visual artifacts.

The actors can produce pages, graphics, interface compositions and other outputs that can be preserved and compared.

This permits measurement of both task quality and actor-specific visual tendencies.

Examples include:

~~~text
TASK / QUALITY
-> correctness
-> required-content coverage
-> accessibility
-> responsive behavior
-> structural consistency

VISUAL ARTIFACT CHARACTERISTICS
-> layout structure
-> whitespace / density
-> spacing tendency
-> typography hierarchy
-> palette / contrast
-> image-to-text ratio
-> visual complexity
-> repeated component patterns
-> cross-task style consistency
~~~

A repeated visual pattern across unseen briefs may become a measurable actor-specific artifact signature.

That is stronger evidence than a one-off subjective statement such as "ISKRA4 has a style." The programme can test whether such a tendency is reproducible, stable and distinct from template reuse.

## 11. Affect-like / "feelings" trajectory

SSI also intends to preserve and compare the project's internal or self-reported "feelings" variables.

For public scientific claims these are treated as **affect-like state proxies**.

Two longitudinal comparisons are planned:

~~~text
EARLY ISKRA AFFECT-LIKE STATE
-> S11-S40 HISTORY
-> S40 AFFECT-LIKE STATE
~~~

and:

~~~text
S40 PRE-WEB AFFECT-LIKE STATE
-> WEB LEARNING
-> POST-WEB AFFECT-LIKE STATE
~~~

The study can then test whether those changes correlate with observable behavior, for example:

- exploration vs conservative reuse;
- recovery after failure;
- uncertainty handling;
- collaboration;
- visual diversity;
- layout complexity;
- stable or changing artifact signatures.

Strict boundary:

~~~text
AFFECT-LIKE SIGNAL != BIOLOGICAL EMOTION
SELF-REPORT != SUBJECTIVE EXPERIENCE
CORRELATION != CAUSATION
CHANGE != PROOF OF SENTIENCE OR CONSCIOUSNESS
~~~

## 12. Three coupled longitudinal measurement layers

The post-S40 programme therefore combines:

~~~text
1. COMPETENCE / LEARNING TRAJECTORY
   skills
   routing
   reuse/adapt/full-flow
   qualification
   regressions
   recovery

2. INTERNAL-STATE TRAJECTORY
   memory/lifecycle
   affect-like state proxies
   checkpoints
   evidence state

3. EXTERNAL ARTIFACT TRAJECTORY
   rendered pages
   graphics
   layout
   style signatures
   quality/accessibility/responsiveness
~~~

The scientific value is in comparing the three layers without assuming in advance that one causes another.

## 13. Why Evidence / ZeroLab matters to the whole programme

Evidence is not the entire SSI project.

It is the measurement and trust layer required to make the broader programme scientifically useful.

Without a reliable evidence path, an observed difference between two agents could actually come from:

- a bad reviewer packet;
- a mismatched candidate;
- transport failure;
- parser failure;
- stale state;
- accidental cross-agent contamination;
- an overwritten historical grade;
- an unreproduced fix.

The active repair work is therefore a prerequisite for credible long-horizon SSI experiments.

The intended relation is:

~~~text
SSI RESEARCH PROGRAMME
        |
        +-> PERSISTENT COMPETENCE / ROUTING / CONSOLIDATION
        |
        +-> LONG-HORIZON S11-S40 DEVELOPMENT
        |
        +-> EVIDENCE / ZEROLAB / REVIEW / RETEST
        |       = measurement trust layer
        |
        +-> S40 FREEZE
        |
        +-> WEB COMPARATIVE STUDY
        |
        +-> LATER EXTERNAL VALIDATION
~~~

The present grant application should be interpreted as support for an already-running research programme.

Public history predating the application documents:

- Micronetwork / persistent competence architecture;
- Router V10;
- Router S10;
- controlled S1-S10 training;
- consolidation and regression gates;
- post-S10 software-domain transfer;
- subsequent S11-S40 R&D work;

The funding request targets a bounded part of that longer programme: stronger evidence, evaluation and validation capacity.

A grant does not establish the scientific claims and does not imply endorsement of SSI. Its value would be to increase the scale, diversity and independence of experiments that the existing architecture already supports.
